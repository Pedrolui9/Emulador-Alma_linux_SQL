Emulador psql — Roles + Alta/Baja/Modificación

Unidad III · Completo

1. Bases de datos

  • CREATE DATABASE compras;
  • \c compras  ← conectar a una base
  • \l  ← listar bases de datos

2. Roles y Usuarios

  • CREATE ROLE desarrolladores NOLOGIN;
  • CREATE ROLE soporte NOLOGIN;
  • CREATE USER salmada WITH PASSWORD 'ClaveSegura123';
  • GRANT desarrolladores TO salmada;
  • SET ROLE salmada;  /  RESET ROLE;
  • \du  ← listar roles
  • SELECT * FROM pg_roles;

3. Permisos (GRANT)

  • GRANT CONNECT ON DATABASE compras TO desarrolladores;
  • GRANT USAGE ON SCHEMA public TO desarrolladores;
  • GRANT SELECT ON ALL TABLES IN SCHEMA public TO desarrolladores;
  • GRANT SELECT, INSERT ON ALL TABLES IN SCHEMA public TO soporte;
  • GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO rol;

4. Alta – Baja – Modificación

  • Alta: INSERT INTO cargos VALUES (3, 'Analista');
  • Alta con columnas: INSERT INTO ciudad (id, des) VALUES (1, 'Asunción');
  • Modificación: UPDATE cargos SET car_descri = 'Gerente General' WHERE id_car = 1;
  • Baja: DELETE FROM cargos WHERE id_car = 2;
  • SELECT * FROM cargos;

5. Consultas de tablas

  • \dt  ← listar tablas
  • \d cargos  ← ver campos de la tabla
  • SELECT version();

6. Eliminar Roles y Usuarios

  • DROP USER salmada;
  • DROP ROLE desarrolladores;
  • REASSIGN OWNED BY salmada TO postgres;
  • DROP OWNED BY salmada;
  • REVOKE desarrolladores FROM salmada;

7. Otros

  • \q o salir → reiniciar el emulador

Explicación de Roles, Usuarios y Permisos

2. Roles y Usuarios

Comando ¿Qué hace? Explicación sencilla
CREATE ROLE desarrolladores NOLOGIN; Crea un rol de grupo Crea un rol llamado desarrolladores que no puede conectarse. Se usa solo para agrupar permisos.
CREATE ROLE soporte NOLOGIN; Crea otro rol de grupo Igual que el anterior, para el equipo de “soporte”.
CREATE USER salmada WITH PASSWORD 'ClaveSegura123'; Crea un usuario Crea un rol que sí puede conectarse y le asigna contraseña.
GRANT desarrolladores TO salmada; Asigna el rol al usuario Hace que salmada herede los permisos del grupo desarrolladores.
SET ROLE salmada; Cambia temporalmente de rol La sesión actúa como si fuera el usuario salmada (para probar permisos).
RESET ROLE; Vuelve al rol original Regresa a ser el superusuario (postgres).
\du Lista los roles Muestra todos los roles/usuarios del sistema.
SELECT * FROM pg_roles; Consulta la tabla de roles Versión SQL del comando \du.

3. Permisos (GRANT)

Comando ¿Qué hace? Explicación sencilla
GRANT CONNECT ON DATABASE compras TO desarrolladores; Permite conectarse Permite al rol conectarse a la base de datos.
GRANT USAGE ON SCHEMA public TO desarrolladores; Permite usar el esquema Permite ver y usar los objetos del esquema public.
GRANT SELECT ON ALL TABLES IN SCHEMA public TO desarrolladores; Solo lectura Solo puede consultar las tablas.
GRANT SELECT, INSERT ON ALL TABLES IN SCHEMA public TO soporte; Lectura + Alta Puede consultar e insertar datos.
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA public TO rol; Todos los permisos SELECT + INSERT + UPDATE + DELETE.

4. Comandos de eliminación

Comando ¿Qué hace? Explicación sencilla
DROP USER salmada; Elimina un usuario Borra definitivamente el usuario salmada. Solo funciona si el usuario no tiene objetos ni privilegios pendientes.
DROP ROLE desarrolladores; Elimina un rol de grupo Borra el rol desarrolladores. Solo funciona si el rol no tiene miembros ni objetos asociados.
REASSIGN OWNED BY salmada TO postgres; Reasigna la propiedad de objetos Cambia el dueño de todos los objetos (tablas, vistas, etc.) que pertenecen a salmada y se los asigna a postgres. Es el primer paso seguro antes de eliminar.
DROP OWNED BY salmada; Elimina privilegios y objetos residuales Borra todos los privilegios que le quedaban a salmada y cualquier objeto que todavía le pertenezca. Se usa después de REASSIGN OWNED.
REVOKE desarrolladores FROM salmada; Quita la membresía Saca al usuario salmada del rol/grupo desarrolladores. Es necesario hacerlo antes de poder eliminar el rol o el usuario.
Resumen rápido
  • ROLE con NOLOGIN → Grupo de permisos
  • USER → Persona que puede conectarse
  • GRANT rol TO usuario → El usuario hereda los permisos del grupo
  • GRANT privilegios ON ... TO rol → Define qué puede hacer el rol
